Reflection Questions
1. Why is it useful to specify action preconditions and effects before asking an LLM to write the planner?

Specifying action preconditions and effects provides a precise description of how actions can be applied and how they modify the state. This reduces ambiguity and helps ensure that the generated planner follows the intended logic of the planning problem. Without clear preconditions and effects, the LLM may generate actions that are invalid or inconsistent with the problem specification.

2. Give an example of an error that could occur if the planner failed to check an action’s preconditions.

If the planner failed to check preconditions, it might allow the robot to execute a PickUp action when the robot and package are in different locations. This would produce an invalid state and could result in a plan that appears successful even though it violates the rules of the environment.

3. Why is a plan that "looks reasonable" not necessarily a valid plan?

A plan may appear reasonable because the sequence of actions seems intuitive, but validity depends on whether every action is applicable in the state where it is executed. A valid plan must satisfy all preconditions and correctly apply all effects. Therefore, a plan must be verified using the formal state-transition rules rather than visual inspection alone.

4. What did the LLM contribute to the implementation?

The LLM assisted by generating boilerplate Python code, suggesting data structures for representing states and actions, and providing an initial implementation of the planning algorithm. This reduced development time and helped translate the planning specification into executable code.

5. What did you have to verify independently?

I independently verified that action preconditions were checked correctly, state transitions were applied properly, and the generated plans actually achieved the specified goal. I also tested impossible planning scenarios and validated that the planner correctly reported when no solution existed.

6. In this laboratory, where is logical reasoning being used?

Logical reasoning is used when determining whether an action is applicable in a given state. The planner checks whether the current state satisfies the action's preconditions before applying it. Logical reasoning is also used when computing the effects of actions and updating the state representation.

7. How is planning related to the search algorithms studied in the previous module?

Planning can be viewed as a search problem in which each state represents a possible configuration of the world and each action generates successor states. The search algorithm explores sequences of actions until a state satisfying the goal condition is found. Logical reasoning determines which actions are valid, while search determines which valid action sequences should be explored.

Optional Prolog Reflection
1. What is the difference between a Prolog fact and a Prolog rule?

A Prolog fact represents information that is assumed to be true. A Prolog rule defines a logical relationship between facts and other rules. Facts provide knowledge, while rules describe how new knowledge can be inferred.

Example:

penguin(polly).

is a fact, whereas

bird(X) :- penguin(X).

is a rule.

2. How does a Prolog query correspond to asking whether something follows from a knowledge base?

A Prolog query asks whether a statement can be logically derived from the facts and rules stored in the knowledge base. If Prolog can construct a chain of valid inferences leading to the queried statement, it returns true; otherwise it returns false.

3. Why might it be useful to use a Prolog program to verify a plan generated by a Python program?

A Prolog verifier provides an independent logical check of the proposed actions. Since Prolog reasons directly from facts and rules, it can confirm whether actions are consistent with the logical description of the environment. This helps detect mistakes that may exist in the Python implementation.

4. What advantage does an independent verifier provide when the original plan was generated with the help of an LLM?

An independent verifier reduces the risk of accepting incorrect plans simply because they appear plausible. LLMs can generate convincing explanations and code, but they do not guarantee correctness. A separate verification system provides objective confirmation that the plan satisfies the formal constraints of the problem.
